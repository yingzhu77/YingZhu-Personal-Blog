# AI写网文的总结和复盘

180章，6卷，约114万字符。一部科幻废土经营流[网文](https://fanqienovel.com/page/7642015401915714584?enter_from=search)。

<!-- more -->

## 为什么要做这件事

最开始的动机还是在某平台刷到了关于小说写作的帖子。简单的说：我想知道现在的AI写长篇小说的效果。（另一个重要原因是上个月小米送的Token根本花不完了，找个地方消耗一下）

而且现在大模型窗口上下文已经到了1M，针对于写长篇小说最难的问题上下文管理，传递信息已经不难了。

## 写作流程长什么样

先说结论：AI写单章的能力已经很强了，但写180章连续小说的难度不在于单章，在于"连续"。

我总结的工作流（不断试错后）是四阶段的：

**写作Agent**读取项目圣经、状态表、伏笔表、最近3章正文，然后输出一章正文加一份写作日志。写作日志只记创作决策（为什么选这个视角、为什么删掉某段对白），不记事实——事实由审稿Agent从正文里直接提取。

**审稿Agent**读取正文、写作日志、所有状态文件，检查连续性（人设有没有漂移、设定有没有矛盾、时间线有没有倒退），然后直接更新状态表、伏笔表和章节摘要。对，它不输出"更新块"让人手动合并，它自己改文件。这一步省了无数复制粘贴的时间。

**一致性检查**每5章跑一次Python脚本，检查食物跳变、伏笔重复、字数超限。全部PASS才能继续。

**修订阶段**每卷结束后做一次风格审读——扫描重复句式、结尾模板、比喻固化，然后批量修复。

听起来很完美对吧？

## 翻车的地方

（以下才是正文。题外话：下面的翻车记录都是我让AI读取我之前文风根据失败记录生成后小修的）

### 翻车一：结尾模板化

写到第三卷（60-90章）的时候，我发现每章结尾都是这个味道：

> 然后他合上日志。
>
> 今天的口粮来自何三的交易——三十份口粮和一百克盐。食物线稳定。
>
> 灰港的灯还亮着。

一章两章不觉得，三十章下来读者（我）要疯了。更离谱的是"管线层的水还在流"这个结尾句，我一度以为它是项目圣经里的不可变设定。

（事实证明不是。它只是AI觉得"这个结尾很有氛围感"之后，复制粘贴了三次。）

后来我做了一次全书修订，把这些重复结尾逐个替换。有的改成对白收束，有的改成动作收束，有的改成环境收束——但不能每章都用同一种，否则又会陷入新的模板。

教训：**AI不会主动发现自己的模式化问题。** 你必须给它具体的检查清单（"最近3章结尾结构不能雷同"），而不是泛泛地说"结尾要有变化"。

### 翻车二：身体反应固化

主角林砚遇到震惊的事情时，永远是"呼吸停了一秒"。180章里出现了13次。

（我还特意数了一下。13次。平均每14章就要呼吸停一次。这人怕不是有哮喘。）

其他角色也好不到哪去。陈野永远是"沉默了几秒，走到窗前"。老关永远是"点了一下头"。周檀永远是"转身走了"。

后来我在写作规则里加了一个"身体反应备选库"——5-8种备选反应，每10章内同一种不能出现超过2次。这才慢慢好转。

教训：**AI倾向于复用它认为"安全"的表达。** 你必须提供备选方案，否则它会一直用同一个。

### 翻车三：食物描写变成了库存报告

我在CLAUDE.md里写了一句"每章正文中至少用一句话交代当日食物来源"。本意是让食物描写融入场景——角色在吃饭时聊今天的口粮从哪来，在交易时提到食物价格，在分配配给时体现资源紧张。

结果AI理解成了：每章结尾加一行"今天的口粮来自何三的交易——三十份口粮和一百克盐。食物线稳定。"

（就像游戏里的每日签到提醒。"叮——您今日的食物来源已记录。"）

后来我把规则改成了"食物来源通过场景呈现，不要在日志中报告库存"。这才把库存报告变回了场景描写。

教训：**规则的措辞比规则本身更重要。** "至少用一句话交代"会被理解成"在日志里加一行"，"通过场景呈现"才会被理解成"让角色吃饭"。

### 翻车四：状态表膨胀

写到100章的时候，状态表已经有几百行了。写作Agent需要读取这个文件，但它不可能从几百行里精准检索到"周檀的污染率当前是多少"。

（就像你把一整本字典塞给一个人，然后问他"第三个字的第七个释义是什么"。理论上信息都在，实际上他只会给你一个大概。）

后来我把状态表分层了——最近3章的详细状态在前面，更早的压缩成一行摘要。伏笔表也分成了"活跃"和"归档"两部分。写作Agent只读活跃部分。

教训：**长上下文不等于有效上下文。** 1M token的窗口可以塞下很多东西，但模型从中精准检索的能力远不如你想象的。

## open-skill：novel-writer

基于这次写作的经验，我把整个工作流打包成了一个Claude Code skill，叫`novel-writer`。如果你也想用AI写长篇小说，可以直接安装使用（记得让ai根据你的主题自行调整一下）。

### skill包含什么

**SKILL.md**（核心规则，约200行）：

- 四阶段工作流（写作→审稿→一致性检查→修订）
- 展示而非告知的具体手法
- 身体反应备选库（5-8种反应轮换使用）
- 结尾多样性轮换表（6种结尾方式：对白、动作、环境、内心、物件、日志）
- 食物场景化规则（不要库存报告，要交易/分配/吃饭的场景）
- 信息去重规则（同一事实最多两个载体）
- 8种常见反模式的识别和修复

**references/style-checklist.md**：

- 结尾检查项（每章必查）
- 重复句式扫描（每10章必查）
- 身体反应频率统计
- 比喻使用记录
- 角色出场频率检查

**references/consistency-checker.md**：

- 自动一致性检查脚本的使用说明
- 检查项：资源跳变、伏笔重复、时间线倒退、角色位置、字数超限

### 怎么用

```bash
# 安装
# 将 novel-writer 文件夹放到 ~/.claude/skills/ 目录下

# 使用
# 在Claude Code中直接说：
# "用novel-writer写一章"
# "用novel-writer审稿"
# "用novel-writer做风格检查"
```

### 它不能做什么

它不能替你决定剧情走向。它不能保证每一章都精彩。它不能让AI突然拥有文学品味。

它能做的是：**防止AI犯系统性的低级错误。** 结尾模板化、身体反应固化、食物描写机械化、信息三重重复——这些问题不会在写第1章时出现，但会在写到第50章时悄悄积累。skill的作用就是在它们积累成灾之前，把它们拦住。

## 最后

用AI写了50万字小说之后，我得到了什么？

得到了一部小说。但更重要的是，得到了一套方法论。

AI不是万能的写手，但它是一个极其耐心的执行者。你给它清晰的规则，它就执行清晰的规则。你给它模糊的规则，它就给你模糊的结果。你给它没有规则，它就给你"管线层的水还在流"。

（说到底，AI写小说和AI写代码一样——最难的不是让AI做，是告诉AI做什么。甲方不好当啊。）
