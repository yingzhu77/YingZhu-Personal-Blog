## AI 写代码很强吗？

答案是毋庸置疑的，有人会拿老虎机、赛博许愿机来调侃，但真用过的人真的停的下来吗？

<img src="/assets/images/posts/图1.jpeg" alt="AI Coding" style="width: 100%; border-radius: 0.5rem; margin: 1rem 0;" />

我的水平绝对是很烂的，属于是之前仅仅跟了一遍视频教程跟着敲过一遍之后没怎么动手再写过代码的人，之后 AI 火起来，更是只会 Ctrl C/V，没有刷过算法，用 Agent 写东西之前也很少会主动写点什么。只是完成课内作业的话，免费的 AI 性能都有些溢出了。而完成项目展示页里的项目，前前后后也不到半个月，虽然没有真正上线，但都是跑通了的。

虽然都在说完成 demo 是不够的，上线还需要许多优化，但是之前仅仅是独自完成前端的东西，做出一个相对"好看"的玩具，要付出的时间成本都是我不能想象的，现在几乎人人都是开口闭口全栈，也可见 AI 对这个行业的冲击了。我只是课内学过 C 语言，姑且有一点编程基础，学了一个月前端，结果发现一个月后写出的页面只要截张图给 AI 已经可以随便复现，甚至细节比我做的好得多。**在这样的情况下人们如何能不感到虚无啊。**

事实也是，这两个全栈项目我除了 [mINDCare-Studio](https://github.com/yingzhu77/mINDCare-Studio) 的前端页面自己完成了一部分（甚至只是一小部分），自己没有写一行代码甚至没有 review 过，纯纯"自然语言编程""面向 AI 编程"了。

## AI Coding 最难的是什么？

这个问题可以从以下两方面回答：

### "人"的方面

怎么做好"甲方"，或者说**怎么写好提示词或约束限制 AI，让它可以实现你预期中的功能**，怎么精准的传达你的意思。既能省 token 也能高效完成任务。遗憾的是，就像大多数甲方一样，我自己有的时候也不知道我到底想要实现的是一个什么样的功能，只能在和 AI 不断拉扯中浪费时间和精力，还有 token。让 AI 实现好几种不同方案，最后感觉还是第一版最舒服的事常有发生。当然，AI 最好的地方就是它不会不耐烦，甚至还能一直捧着你 work...

<img src="/assets/images/posts/图4.jpg" alt="AI 对话" style="width: 100%; border-radius: 0.5rem; margin: 1rem 0;" />

但这不代表你可以完全不思考，毕竟 token 还在跑（哭？哭也算 token 哦）。发问或者推进计划之前多想一下无疑是对的。本来开发都说是前端后端全栈工程师，现在似乎工作内容更接近产品经理了？最重要的还是要**肯"折腾"**吧，现在知识壁垒被打破，只要维持热情，这些问题其实并不大。如果说还有什么限制，那只能是个人的想象力了，**你做出的决定，你的审美和判断终究决定了上限**。

### "工具"的方面

大多就是上下文管理、切换窗口交接任务、还有什么时候压缩对话之类的。技术门槛之类的问题其实并不大，你完全可以开一个窗口开发一个窗口 debug，甚至用一个 Agent 写提示词，把你预期实现的效果转化成专业的术语让另一个 Agent 精准的执行之类的。这里有些提示词模板，感觉还挺有用的：[codex-cookbook](https://github.com/aruis/codex-cookbook)。

当然如果需要做的像模像样甚至真正上线，无疑需要很专业的提示词，可以考虑在计划时让 AI 不断提出反问，所谓**"对齐需求"**，直到它完全理解每一个计划细节，以及对于技术栈的取舍，不懂具体就让它分析利弊，分析计划可行性，甚至提出发散性建议。最重要的是写好预期需求、规模与目标，要真正上线需要跑通的那么多条测试，每个模块需要实现的功能之类的。当然如果一开始没那么明确也不必继续写清，遵循所谓 **MVP 原则**就好。AI 可以给你二三十种方案，但做决定的人只有你一个人，不必急于选择，因为它写代码效率已经够高了。

当设计完计划后第一件事，就是编辑 `CLAUDE.md` 约束注入提示词，诸如绝对不要提交真实 API、绝对要进行最小程度改动不要动其他功能等等...

当项目太大的时候，频繁切换窗口直接把一整个上下文都塞进去无疑会造成很沉重的 token 负担，所以我经常采取的方案是**交接的时候让上一个窗口直接写好下一个窗口的任务提示词**，包括要修改的地方，做必要的约束（哪些地方不能动也不需要读入，只做局部变动），验收标准和实现目标。当然现在很多 Agent 都可以用 skill 或者 MCP 实现自行分配子 Agent 完成任务了...真是可怕。

说到这里，根据自己的项目去**装一些 skill、MCP 是很有必要的**，这些跟你具体的项目相关，建议直接问 AI 让它给安装建议，有余力自行检索就更好了。甚至于大多数不知道下一步要做什么的时候都可以问 AI，它总能给你一个让你满意的答案。控制成本，尽量减少 token 消耗也是门学问，当然这里不多赘述了，相信亲自上手以后会更有体会。

## 关于未来...

<img src="/assets/images/posts/图3.jpeg" alt="未来" style="width: 100%; border-radius: 0.5rem; margin: 1rem 0;" />

几乎每过不到一个月，都要出一个新"旗舰"大模型，DeepSeek V4、GPT-5.5，大模型一代一代迭代，我们只能站在巨人的肩膀上，倒不如说迄今为止所有的工作，包括 Prompt 提示词工程、RAG 检索、再到接入 MCP、又到轻量化的 Skill，都是为了更好的发挥大模型的能力。有人说这只是泡沫，有人说这是新的工业革命，谁也说不好明天会发生什么，作为普通的年轻人，只能尽力跟着时代去"折腾"了。

人们都在焦虑，经济下行，就业环境，这些确实是实实在在的问题，无能为力的我们除了抱怨和继续向前还能做什么呢？这就是我们需要承受的大时代落在每个个体身上的所谓**"时代的阵痛"**吧。

说回个人，AI 拓展了太多可能性，个人能做的比之前多了太多，暂且生产力过剩导致的问题丢回给负责他们的人吧，前人费劲心力栽树，越来越接近他们曾经梦寐以求的"自然语言编程"的 AI 编程，我们后人怎么能不尽情乘凉呢。
